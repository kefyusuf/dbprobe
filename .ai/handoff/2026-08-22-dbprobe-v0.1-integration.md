### MySQL schema fingerprint v1

Integrated signal:

`mysql.schema.structural_fingerprint = v1:sha256:<64 lowercase hex>`

Coverage:

1. tables/objects
2. columns
3. indexes
4. key/constraint relationships
5. CHECK clauses
6. FK referential actions

Bounds:

- 1 MiB per field
- 4 MiB per canonical record
- 100,000 rows per metadata group
- 64 MiB total canonical metadata budget

Any metadata surface failure produces no fingerprint. Raw DDL/default/expression/CHECK/FK metadata never crosses the adapter boundary; only the opaque hash does.

Focused normal/race tests passed. Live MySQL Docker gate remains pending.

### Safe plan-only EXPLAIN

Integrated optional `adapter.PlanExplainer`; `adapter.Runtime` was not widened.

MySQL execution envelope:

- single conservative `SELECT` only
- no multi-statement
- no `EXPLAIN` / `EXPLAIN ANALYZE` input
- no DML / `WITH` MVP support
- no locking clauses
- no `INTO`
- no `:=` session assignment
- statement max 64 KiB
- 5-second context timeout
- `BeginTx(ReadOnly=true)`
- only `EXPLAIN FORMAT=JSON <validated SELECT>`
- `ROLLBACK`, never commit
- raw plan max 1 MiB
- explicit plan metadata allowlist sanitizer
- application accepts only `Estimated=true` and `Sanitized=true`
- input statement uses `json:"-"`

`query.explain` capability probe uses the actual feature surface: `EXPLAIN FORMAT=JSON SELECT 1`.

Focused execution/sanitizer/application normal/race tests passed. Full Cobra and live MySQL gates remain pending.
